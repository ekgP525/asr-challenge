CampusVoice-RT

야외 잡음 속에서 한국어 음성을 실시간으로 받아쓸 때, 잡음이 정확도와 응답 지연을 함께 어떻게 무너뜨리는지 평가합니다.

주 지표
잡음 4조건 평균 CER
지연 제약
p90 최종 지연 ≤ 1.0초
잡음 조건
SNR 20 / 10 / 5 / 0 dB
참가자
이다혜 202422051

시나리오

  • 학생회관 앞 잔디밭에 있는 마스코트와 음성으로 대화하는 상황을 가정합니다.
  • 잔디밭은 야외라 주변 대화, 바람, 차량, 행사 소리 같은 잡음이 큽니다.
  • 대화가 자연스러우려면 사용자가 말을 마친 직후 1초 안에 인식이 끝나야 합니다.

문제

  • 잡음이 커지면 인식 오류만 늘어나는 것이 아니라, 음성 구간 검출(VAD)이 말이 끝난 시점을 늦게 잡거나 발화 중간에서 끊어 응답 지연이 함께 흔들립니다.
  • 스트리밍 인식에서는 잡음이 클수록 이미 화면에 표시한 부분결과를 다시 고치는 일이 잦아집니다.
  • 기존 공개 벤치마크는 정확도와 속도를 따로 보고하며, 잡음 수준에 따라 둘 사이의 관계가 어떻게 달라지는지는 다루지 않습니다.

목표

  • 공개 한국어 코퍼스에 야외 잡음을 SNR 단계별로 합성한 평가셋과 생성 스크립트 공개
  • 같은 스트리밍 프로토콜에서 잡음 조건별 CER, 최종 지연, 종료 검출 오차, 부분결과 수정률을 측정하는 평가 코드 공개
  • Qwen3-ASR 1.7B·0.6B의 오프라인·스트리밍 추론을 베이스라인으로, 잡음이 커질 때 정확도–지연 위치가 이동하는 양상 제시

과제 정의

입력은 야외 잡음이 섞인 16 kHz mono 한국어 음성이고, 출력은 한국어 텍스트입니다. 음성은 0.5초 청크 단위로 실시간 도착 시각에 맞춰 공급되고(가상 시계 시뮬레이션), 모든 시스템은 같은 VAD 설정 아래에서 동작합니다. 학습 데이터와 모델 선택은 자유입니다.

Track A 정확도

잡음이 커질수록 인식 오류가 얼마나 늘어나는가
  • 조건: Clean, SNR 20 / 10 / 5 / 0 dB
  • 지표: 조건별 CER ↓

Track B 실시간성

잡음이 커질수록 응답이 얼마나 늦어지고 흔들리는가
  • 조건: Track A와 동일
  • 지표: 최종 지연 p50 / p90 ↓, 시작·종료 검출 오차와 조기 절단율 ↓, 부분결과 수정률 ↓, 첫 부분결과 지연 ↓, RTFx ↑
  • 측정 GPU: NVIDIA L4 고정

순위 규칙

  • 잡음 4개 조건 각각에서 p90 최종 지연이 1.0초 이하인 시스템만 메인 순위에 포함하고, 한 조건이라도 넘으면 순위 없이 따로 표시합니다.
  • 메인 순위는 잡음 4개 조건 평균 CER이 낮은 순이며, 같으면 잡음 4개 조건 평균 p90 최종 지연이 짧은 쪽이 앞섭니다.

데이터셋

평가셋은 재배포가 허용된 공개 한국어 코퍼스의 테스트 분할에서 발화를 뽑고, 야외 잡음을 고정 시드로 합성해 만듭니다. 음성, 정답, 합성 기록을 모두 공개하며 스크립트로 같은 평가셋을 다시 만들 수 있습니다.

구성출처내용발화 수라이선스

잡음 합성

  • 잡음 종류: 주변 대화(군중), 바람, 차량, 야외 행사 소리. FSD50K에서 라벨로 고르되 CC0·CC BY 클립만 사용하고, Freesound id·업로더·라이선스를 클립별로 공개합니다. 필요한 클립만 내려받으므로 FSD50K 전체(32 GB)가 필요 없습니다.
  • 원본 발화는 먼저 ITU-T P.56 활성 음성 레벨이 −26 dBov가 되도록 정규화합니다. 원본 녹음 레벨이 50 dB 넘게 차이 나서, 그대로 두면 양자화와 VAD 반응이 교란 요인이 됩니다.
  • SNR 20 / 10 / 5 / 0 dB. 발화마다 잡음 종류, 파일, 시작 위치를 시드 고정으로 무작위 배정하고 기록합니다.
  • SNR은 ITU-T P.56 방식의 음성 활성 구간 레벨 기준으로 계산합니다. 짧은 발화에서도 쉼 구간 때문에 SNR이 흔들리지 않습니다.
  • 야외 환경이라 실내 잔향은 넣지 않습니다.
  • 잡음 구간은 발화 앞뒤로 1초씩 더 길게 둡니다. 발화가 끝난 뒤에도 잡음이 이어져야 VAD 종료 검출이 실제처럼 어려워집니다. Clean 조건의 앞뒤 1초는 완전한 무음 대신 −60 dBov의 마이크 노이즈 플로어입니다. 완전한 0은 실제 마이크에서 나오지 않고 LLM 기반 인식기가 그 구간에서 텍스트를 환각하게 만듭니다.
  • 같은 발화의 4개 SNR은 같은 잡음 클립·오프셋을 레벨만 바꿔 씁니다. 잡음 범주는 발화 번호 기준으로 배정해 소스별로 균등하고 처리 순서와 무관하게 결정적입니다.

정답 발화 구간

  • 발화 시작·종료 시각은 잡음을 넣기 전 원본 음성에 Silero VAD(threshold 0.5, min silence 300 ms)를 적용해 구하고 manifest에 기록합니다. 이 값은 엔드포인터 설정과 분리되어 고정됩니다.

참고

  • Qwen3-ASR 기술 보고서는 한국어 성능을 FLEURS로 보고합니다. Clean 조건 점수는 모델이 이미 접했을 수 있는 기준점으로 보고, 잡음 조건에서 얼마나 떨어지는지를 중심으로 해석합니다.

평가 방법

지표계산
CER ↓정규화 후 공백을 제거한 문자 단위 편집거리 ÷ 정답 문자 수

시작·종료 검출 오차 ↓VAD 시작 시각 − 정답 시작 시각, VAD 종료 검출 시각 − 정답 종료 시각의 중앙값. 정답 종료보다 먼저 끊긴 발화의 비율(조기 절단율)과 VAD가 발화를 아예 못 잡은 비율을 함께 보고

텍스트 정규화

  • 문장부호 제거, 연속 공백 축약, 영문 대문자 통일, 소수점 구어 표기 "쩜" → "점"
  • 아라비아 숫자는 한자어 읽기로 통일 (2026 → 이천이십육, 1,000 → 천). 정답과 모델 출력 모두 같은 정규화기로 변환하며, 고유어 읽기가 필요한 숫자 문장은 평가셋에서 제외

지연 측정 프로토콜

  • 가상 시계: 청크 i는 스트림 시각 (i+1)×0.5초에 도착하고, 시계는 도착 시각까지 전진한 뒤 VAD·모델 호출의 실측 처리 시간만큼 더 전진합니다. 처리가 공급을 따라가면 실시간 재생과 같고, 못 따라가면 대기 지연이 누적됩니다.
  • 엔드포인터: Silero VAD, threshold 0.5, min silence 500 ms, 32 ms 프레임 단위. 원본 424발화의 문장 내 최대 쉼이 p95 0.5초라 300 ms면 clean에서도 15.6%가 조기 절단되고, 800 ms면 종료 검출만으로 0.8초를 써서 1초 예산이 무의미해집니다.
  • VAD 게이트: 발화 시작이 검출된 뒤에야 ASR에 오디오를 넘깁니다(시작 200 ms 전부터). 게이트 없이 흘려 넣으면 접두부를 고정하는 스트리밍 인식기가 발화 전 구간에서 환각한 문장을 고정해 발화 전체를 엉뚱한 문장으로 바꾸는 일이 생깁니다(사전 점검: 같은 오디오가 clean 18%, 20 dB 1.4% CER).
  • 오프라인 시스템: VAD 종료 검출 시점까지의 구간을 한 번에 추론. 스트리밍 시스템: 0.5초 청크를 이어 넣고 부분결과가 바뀔 때마다 시각 기록
  • 모델 로드 후 측정과 같은 경로로 3발화 워밍업, 발화당 1회 측정. B2 40발화를 3회 반복해 1회 측정과 3회 중앙값의 차이를 별도로 보고

실행 환경

베이스라인

Qwen3-ASR 1.7B·0.6B를 추가 학습 없이 사용합니다. 모델 크기와 추론 방식을 2×2로 교차해, 잡음이 커질 때 각 요인이 정확도와 지연에 주는 영향을 분리합니다.

ID모델추론 방식비교 대상
  • 네 시스템 모두 vLLM 백엔드(qwen-asr[vllm]). qwen-asr의 스트리밍이 vLLM 전용이라 오프라인도 같은 백엔드로 맞췄습니다.
  • 스트리밍(B2, B4): 모델 디코드 청크 1.0초, 접두부 미고정 청크 2, 롤백 토큰 5 (qwen-asr 기본값). 청크마다 지금까지의 오디오 전체를 다시 디코드하므로 발화가 길수록 한 스텝이 느려지고, 그 누적이 지연 지표에 그대로 반영됩니다.

실행: python baseline/run_qwen3_asr.py --config baseline/configs/B1.json --manifest data/eval/manifest.jsonl --out-dir runs/B1

리더보드

모든 시스템은 같은 평가셋, 같은 VAD 설정, NVIDIA L4에서 측정했습니다. 잡음 4개 조건 각각에서 p90 최종 지연이 1.0초 이하인 시스템만 순위를 받고, 넘는 시스템은 '지연 초과'로 표시됩니다.

결과 해석

  • 네 시스템 모두 잡음 조건 중 하나 이상에서 p90 최종 지연이 1.0초를 넘어 메인 순위는 비어 있습니다. 가장 가까운 것은 B4(0 dB에서만 1.08초)이고, B2는 5 dB부터, B3는 10 dB부터, B1은 Clean에서도 넘습니다. 정확도 순서(B1 < B2 < B3 < B4)와 지연 순서는 정반대입니다.
  • 지연이 늘어나는 주 원인은 잡음 속 종료 검출입니다. 종료 검출 지연 p90이 Clean 0.56초에서 0 dB 0.99초로 늘고, 그 위에 오프라인은 종료 후 전체 추론(B1 p90 0.80초)을, 스트리밍은 마지막 청크 처리(0.15~0.29초)만 더합니다.
  • CER은 두 경로로 오릅니다. 엔드포인터가 문장 내 쉼에서 발화를 일찍 끊는 조기 절단이 Clean 43개에서 0 dB 64개로 늘고(절단 발화의 CER 66~75%), 절단되지 않은 발화의 인식 오류도 2.5~4.3%에서 12~19%로 4~5배 늘어납니다. 엔드포인터는 모든 시스템이 공유하므로 순위에는 영향이 없습니다.
  • 스트리밍은 잡음이 커질수록 이미 보여준 텍스트를 고치는 일이 늘고(수정률 B2 19% → 38%), 발화 시작 전에 잡음만 듣고 텍스트를 내는 비율도 3% → 7%로 늘어납니다.
